合成测试只使用本地样本和隔离状态，不操作真实账户、OAuth grant 或研究发布。正常短期令牌刷新仍遵循现有授权，不扩大 scope 或延长连接期限。旧独立 MCP 条目只通过显式 `--migrate-legacy` 操作迁移；升级和本次测试不会自动删除它。

执行命令：`python -B -m unittest discover -s client -p "test_*.py"`；`python -B -m unittest discover -s scripts -p "test_build.py"`。首轮仅一个旧测试仍期待 17 个工具而失败，按新增工具契约修正为 20 后完整客户端回归通过。新 EXE 从清洁源码提交 `f7b19c920ab599071f43187dac2067c343408ba3` 构建，22,611,884 字节，SHA-256 `e53530ed46e7b785e7795eb9aac26e11140432b51cb2b92b655f989bf3dbb36f`。构建结果与公开边界检查通过；该产物未签名。

交叉审查发现 SDK 默认可能转换参数类型并丢弃未知字段，因此三个新工具在 SDK 类型转换前增加独立原始参数检查，并在发现 schema 中禁止额外字段。真实协议 handler 的合成测试覆盖 16 个无效输入反例、null 版本／零游标等合法请求及旧工具兼容；错误不回显输入。现有 OAuth scope 和旧工具行为保持不变。

仍需分别验证全新 Windows 用户安装、已有客户升级、权限隔离、真实数据版本切换与发布游标分页，以及安全停止后的恢复。若环境、访问或签名条件不足，应记录 BLOCKED／NOT_RUN，不记作通过。

本地去重自动测试合计291项通过，真实浏览器另计19项。网页首次移动宽度验收发现目录版本长文本横溢，已修复并复测通过；服务端路由测试的会话类型断言按现有web身份修正后通过。生产账户停用、到期及撤销仅在隔离数据中验证，不更改真实客户状态。候选包中的本页是打包时快照，CI及上线结果以对应Release说明和main上的后续验收补充为准，旧标签和包不会重写。
